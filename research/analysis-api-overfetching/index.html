Critical Information Disclosure via API Over-fetching

DATE: 2026-08-12 SEVERITY: CRITICAL CATEGORY: SENSITIVE_DATA_EXPOSURE / API_SECURITY

EXECUTIVE SUMMARY

This analysis documents a Critical security flaw on a developer showcase platform. The application's backend API returns excessive data (Over-fetching) when a user's profile is viewed. This metadata leakage includes highly sensitive information such as private email addresses and GitHub Personal Access Tokens, which are never intended to be visible to the public.

EXPLOITATION_POC (VIDEO)

TECHNICAL_WALKTHROUGH

The discovery was made by intercepting background API calls triggered during standard navigation on the platform.

1. Navigation: Browsing the "Trending Repositories" section and selecting a project led to an author profile page (e.g., vincent_dev).

2. API Interception: While the frontend UI only rendered the user's Full Name, Bio, and Projects, an investigation of the background traffic via Burp Suite revealed a direct call to the user data endpoint.

HTTP_API_REQUEST
GET /api/v1/users/vincent_dev HTTP/1.1
Host: redacted.com:5006
Cookie: session=eyJ1c2VyIjoidGVzdEByZWRhY3RlZC5jb20ifQ...

3. Sensitive Data Leakage: The server's JSON response contained the full user object from the database. Critical internal fields were exposed in the response body, despite being omitted from the user interface.

VULNERABLE_JSON_RESPONSE
{
    "full_name": "Vincentius Adrian",
    "email_private": "vincent.private@redacted.com",
    "github_username": "vincent-codes",
    "github_id": "GH-9928112",
    "github_token": "ghp_u98XzL291mKlapQ0192vBxzZq99102Mm",
    "projects": [...]
}

4. Impact Analysis: The exposure of the github_token is classified as Critical. An attacker could use this token to gain full unauthorized access to the victim's GitHub repositories, private codebases, and production environments. Additionally, the leak of email_private violates user privacy and facilitates targeted social engineering attacks.

REMEDIATION_STRATEGY

To mitigate this vulnerability, the backend must implement Data Transfer Objects (DTOs) or response filtering. The API should only return a subset of user data that is strictly necessary for the frontend to render. Sensitive credentials like tokens and private contact information should never be included in public API responses.
